# 中文字体设计

将中文风格需求变成真实、可验证的字体。默认以汉字、中文标点和数字为验收重点；保留底库自带西文用于兼容，中英配套仅在用户明确要求时另行处理。

基础轮廓来自许可允许修改的字体。参考用于分析风格；不凭一张图承诺原创几万个汉字。自动路线支持原生变体轴；核心字编辑路线支持静态 glyf 字体的显式轮廓替换，尚无偏旁识别或全字库风格传播。

## 范围与选型

先读 [需求沟通与确认](references/intake.md)。从已有对话提取用途、简繁范围、风格、参考和必需文字；只询问缺项。默认先沟通风格并主动邀请用户提供 reference，再制作；已有图片直接使用，不重复索要。用户没有图片或明确让代理决定时，提供可比较的方向小样，不因缺少附件卡住工作。

### 三个有意义的确认

1. **需求与参考**：确认用于标题/海报、正文/UI 还是品牌字，简体/繁体/两者，以及喜欢和避免的笔形。不同图片可分别作为字体、结构或 handbook 版式参考，先厘清角色。
2. **核心字样**：参考中确定的同字对照，加少量未出现过的新字，使用实际 TTF/OTF 渲染。让用户指出想保留或调整的部分；不要把“参考里一个字对了”当作整套设计已获认可。
3. **扩展效果**：扩字前展示一段新文案和复杂字，说明哪些是参考轮廓、哪些是底库与规则延展。方向已确认且用户明确要求直接做完整包时继续完成，不逐字或逐文件重复询问。

把确认用于解决真实设计选择，不询问是否可以读取、试排或打包这些已经授权的工作。用户已说“按这个做”“你决定”时按其授权推进；仅在新出现、会改变方向的歧义上追问。流程不要求固定对话轮数。

### 简繁同时支持

先读 [参考匹配与简繁路由](references/reference-matching.md)。图片展示的简繁、用户输出的简繁、视觉风格是独立信息；最新明确选择优先，不从聊天输入或一个「葉」推断产品范围/地区。

- 简繁都要时，可在同一字体中保留两套不同码位的字符，分别验证用户简体与繁体语料，不自动强制拆成两份文件。
- 若用户需要不同台/港/简中字形规范，明确优先地区，检查 locl；无法在同一文件中可靠满足时再分地区配方/文件。保留两种字符不等于同一码位同时具有所有地区字形。
- 本包的 [简体入口](../make-simplified-chinese-font/SKILL.md) 与 [繁体入口](../make-traditional-chinese-font/SKILL.md) 共用此核心，不是互不兼容的引擎。双范围需求由此入口统筹。
- 纯西文字体仍使用独立英文流程；底库自带西文仅作兼容，不冒充已设计一套英文字体。

未改轮廓只能标为底库选型样例；精确参考字与其他新字的匹配须分开评估。完整指所选字库覆盖，不等于从一张图恢复原字体的所有字。

先读 [设计与底库选择](references/design.md)，比较 2–3 个骨架、地区和用途合适的候选。保留原生字重与字宽，不伪造不存在的字重或用拉丁 x-height 指标拟合汉字。

- 正文/UI：选型时优先保证 common-3500 和 punctuation-digits 完整；正式通用版本将它们加入 required_coverage_profiles。standard-8105 单独显示。达不到目标时换底库或明确保留有限覆盖，不以总字数代替验收。
- 标题/书法/品牌字试样：允许有限覆盖，但展示实际缺字与适用用途；完整底库也可能缺少常用字。
- 繁中：按已确认地区使用 zh-Hant-TW 或 zh-Hant-HK。内置 big5-common-5401 为 Big5 一级字符映射检查，不能代替地区字形规范认证。
- 简繁兼容：配置 language 仍是优先地区；另外用 coverage 分别检查简体字表、繁体字表和两种用户语料，不能凭一个地区的 report 声称两边都完整。

快速预览可用子集；正式交付默认保留所选底库完整覆盖。完整只相对于底库，不等于全部 Unicode 汉字或逐字审美验收。

## 执行

Python 3.11+，在独立虚拟环境安装 requirements.txt；不自动安装系统字体。SKILL_DIR 为本技能绝对路径。

```sh
python "$SKILL_DIR/scripts/cjk_font.py" inspect base.ttf --text-file corpus.txt --out inspection.json
python "$SKILL_DIR/scripts/cjk_font.py" preview base.ttf --config design.json --text-file corpus.txt --license OFL.txt --out preview-v1
python "$SKILL_DIR/scripts/cjk_font.py" export base.ttf --config design.json --text-file corpus.txt --license OFL.txt --out release-v1
```

读取 [构建合同与配置](references/build.md) 再执行构建。preview 强制子集，export 强制完整覆盖，即使旧配置 subset=true。输入必须是完整底库；不得从已裁剪试样恢复不存在的字。

同一配方换文案时使用 preview 的 --previous-build 累积字符；不重新分析同一参考。不静默回退、归并简繁或规范化用户文字来消除缺字。

整套规则延展前先读 [整套延展的边界与验证](references/full-font-styling.md)。用户需要改收笔、转角或少量品牌字时，读取 [核心字编辑](references/glyph-editing.md)。先用 glyph-template 导出源轮廓与全部别名，编辑明确的 SVG 路径数据，再将清单嵌入配方。原生轴不能完成的设计不要口头宣称已经实现。

## 验收与交付

最终用户下载包采用“TTF/OTF 在最外层，其余全部放入 `资料/`”的结构；多字重平铺，不让用户进入多个构建目录寻找安装文件。使用 [打包与交付](references/packaging.md) 中的脚本整理，保留网页试字和许可。

制作 handbook/preview 时先读 [字样册版式](references/handbook.md)。默认采用用户已指定的顺序：有字体性格的大标题（字体名字）、短 description、各真实字重独立字样、数字和符号。不要将这一版手写风格套成所有字体的默认风格。

- 构建只在全部自动检查成功后原子提交正式目录；失败不会留下可误用的半成品。
- 保留所有 Unicode cmap 表的映射，比较实际排版后的字形轮廓、cluster 和定位；XML 必须重新编译为二进制并复核。中英片段分段排版，但不宣称支持完整双向排版或 IVS/竖排。
- 输出字体、WOFF2、CSS、许可、FONTLOG、配方、语料、覆盖报告和 HTML 样张。中文名写入字体内部，ASCII 名用于稳定工程标识；实际应用的字体菜单行为仍需实机查看。
- 报告分开显示源底库/输出适用的 3500、8105、Big5 常用字表与标点数字覆盖。字表数据已记录官方来源、版本、提取方法和 SHA256；码位覆盖不是字形规范认证。
- 编辑记录列出实际改过的 glyph、全部别名、前后轮廓摘要及字宽；继承底库的字符不得计为原创设计。
- 人工查看 16/24/48/96 px、复杂字、标点、换行和实际加载字体；小字用途另测 12/14 px。正文与书法标题使用不同验收目标。
- 检查报告仅声明本次运行的项目；FontBakery、OTS、地区专项、IVS、竖排和逐字视觉质量未验证时明确列出。

历史实测及本版结果见 [验证记录](references/validation.md)。代码回归测试位于 tests/test_workflow.py，按文件说明提供底库、许可和配方后运行；小夹具不能代替完整字体验证。
