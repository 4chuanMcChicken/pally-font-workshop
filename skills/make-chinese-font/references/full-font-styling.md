# 从参考字延展完整设计版

先读 [需求与确认](intake.md)。用户要完整 kit 时，先明确是底库重命名、有限核心字定制、还是完整骨架上的规则处理；不能把第一个步骤描述成第三个。

## 三类结果分开报告

- **参考字校准**：已提供字形的明确轮廓与留白，核对 Unicode、别名和原图辨识。可从清楚的自有/授权字稿转换为轮廓；来源未核验时保留来源事实，不据此承诺可公开商用。低分辨率图限制轮廓精度。
- **新字延展**：为未出现的字选择骨架，制定比例、笔画、端点、转角和撇捺等规则。先看代表性新字，不能拿参考字的局部重合度当整套相似度。
- **完整交付**：保留所选底库完整 cmap，核对目标字表和输入语料，提供可安装字体、手册、试字与实际设计范围。完整相对于所选底库，不是全部 Unicode 或逐字原创。

## 需要整套几何处理时

这是项目设计源的处理分支，核心 cjk_font.py 没有自动风格学习命令。只有用途和小样适合时才使用；不要将葉光参数作为通用 preset。

1. 选择许可允许修改、字形地区和覆盖合适的完整源字体；独立保存原文件 SHA256。
2. 用一组不同结构字拟定共享规则；保持 advance/必要布局关系，或明确记录确实调整过的指标。比例拟合不能替代笔形设计，也不能解决所有部件和例外。
3. 若需要分解组件，先从未修改的完整 glyph set 读出全部目标轮廓，再统一提交，避免边读边改导致组件被重复处理。列出影响的 glyph 与码位别名，检查共享组件、替代字形和未编码 glyph。只改了一部分就如实记录，不能说全库都处理了。
4. 对转角、长斜线等修改设置适合该项目的幅度与例外。检查闭合路径、负形、极端密集字、空轮廓和行框；变动过轮廓的 hinting 不能直接当作仍然有效。
5. 将经验证的项目设计源交给核心构建器 export。核心的 rename/XML/WOFF2 等不变性检查此时针对“处理后的设计源”，必须另附“原底库 → 设计源”的修改记录，避免报告只显示 original outlines retained 而隐藏此前变化。
6. 检查导出后已确认参考字的几何仍然保留，目标字表无新增缺失，完整映射与未计划改变的 advance 没有丢失。渲染多字号、复杂字、整段文字并测试实际输入。

## 葉光已验证的范围

本次样例保留 18,145 个码位、13,215 个汉字码位，Big5 一级映射范围 5,401/5,401 覆盖；以霞鹜漫黑为骨架，处理 17,182 个全宽 glyph，序列化轮廓实际变化 17,180 个，并单独保留参考「葉」。数字是该版本实测结果，不能复制到其他字体。

该结果是规则延展设计版，没有训练自动字体生成模型，也未从一字恢复完整原字体；没有逐字完成全部汉字的审美、地区规范或 hinting 验收。参考截图授权未知时，这种实验不能被称为已经获准开源发行的完整字体。
