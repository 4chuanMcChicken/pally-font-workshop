# 核心字轮廓编辑试验

用于少量已存在汉字的明确设计变更，例如逐字编辑收笔、切角和留白。不是从参考图自动识别偏旁或把风格传播到整套字体的模型。

## 工作流程

1. 使用许可允许修改、已验证的静态 glyf 底库。可变字体须先实例化并验证静态结果；CFF/CFF2 不进入此编辑分支。
2. 导出原始轮廓：

```sh
python "$SKILL_DIR/scripts/cjk_font.py" glyph-template base.ttf --text "一口" --out glyph-edits.json
```

3. 清单包含底库 SHA256、UPM、每个 glyph 的全部 Unicode 别名和 SVG path 数据。路径坐标为字体单位、Y 轴向上；不接收整份 SVG XML、脚本、外部引用或图片描摹命令。
4. 由代理或字体设计师编辑明确的 path 数据，所有轮廓以 Z 闭合，保留内部负形与正确方向。记录 note 描述改动和轮廓来源；参考字体不进入构建。
5. 将整个清单对象嵌入 design.json 的 glyph_edits 字段，再执行 preview 或 export。核心字及其别名自动加入验证语料；其他字段和命令与普通构建相同。
6. 查看原字/改后字在大字号与 12/14/16/24 px 的效果；确认字宽、重心、收笔、内白和邻字关系。保留完整底库，先验收这一组字后再逐批扩展。

## 引擎边界

- 验证源文件 SHA256、UPM 和坐标系统，防止把旧轮廓套在不同底库/字重上。
- 一个条目只能改一个 glyph，必须明确列出它全部 Unicode 别名；禁止暗改共享别名。
- 若目标被其他复合 glyph 当作组件引用，拒绝自动传播。先在专门设计源中解决组件与依赖，再制作新底库。
- 不新增码位，不改变 advance；更新 LSB，检查非空闭合轮廓、有限坐标和支持的字体/行框边界。
- 支持 SVG path 的二次曲线与立方曲线；立方曲线转 TrueType 二次曲线误差上限 0.5 字体单位，然后量化。已有 hinting 不自动转移到新轮廓；小字须实测。
- 记录修改前后轮廓摘要、涉及字符与字宽。摘要变化表示轮廓表达变化，不自动证明审美改善或原创程度。
- 一处轮廓编辑成功不代表全部汉字已定制；该版本未实现部件位置变体、自动收笔滤镜或跨字重插值。
