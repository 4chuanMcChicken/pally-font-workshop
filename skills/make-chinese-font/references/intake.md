# 需求沟通、Reference 与确认

## 开始先了解真实需求

先读历史回答、附件和已确认的小样，只补充影响设计的缺项。一轮尽量聚焦 2–3 个容易回答的问题，可把有关信息合并，按用户熟悉的语言交流：

- **用途和感觉**：“主要用在海报标题、品牌字，还是正文/UI？希望更科技、书写、古典、可爱，还是有其他方向？”风格词只是起点，继续落到粗细、宽窄、圆尖、规整/自由等可观察特征。
- **字符范围**：“简体、繁体，还是同一套同时兼容？”只有繁体且地区会影响使用时，再确认台湾/香港/无特定地区要求。用户没有地区要求可先做标明地区未验收的设计版，不擅称规范字体。
- **参考**：主动邀请用户发 1–3 张喜欢的字体、招牌、字稿，最好清晰并包含多个不同结构的字；请其指出最喜欢的部分和不想要的感觉。有名字、原文件、链接或自有字稿时一并利用。请求图片附件用普通对话，不塞进只支持文字的选择工具。

已有合适图片就直接分析；仅在辨识或结构恢复确受分辨率影响时请求原图/局部清晰图，同时继续不依赖它的工作。不要要求用户重发仍可访问的附件。

没有 reference 也能推进：用户说没有、请代理推荐或已授权自行决定时，用同一组字给 2–3 个有差异的方向，让用户比较。不要把一种最熟悉的底库当作所有风格的答案。

## 参考的角色必须清楚

分别记录每张图用于字形/笔形、结构/字面、颜色/材质，还是 handbook 版式。一个字体参考和一个样张排版参考可以同时存在，不把排版参考的英文字体套到中文设计。多个风格互相冲突时问清主次，不擅自平均混合。

把观察转成简短的设计约定，例如“横向舒展、端点略斜、撇捺有弧度；避免圆头与密集中宫”。不要只复述“科技感/高级感”。识别不确定的字显式标疑点，不自行补成一个名字或短语。

如果用户要高度还原，说明已有字可逐字核对，而未出现的字仍需延展设计。知道原字体名称时先核对公开来源和许可；未知来源可先做本地风格研究，不宣称整套结果已获商用/开源授权。不把许可未明的图中文字混入开源底库后给整套套用 OFL 保证。

## 用可看的结果确认

**需求确认**：用几句话归纳字形范围、用途、风格关键点、参考角色、必需文案和覆盖目标。用户先前已经说清的直接记录；确有新选择才问，不机械发送“请确认以上全部”。

**核心字确认**：通常以 8–16 个字为起点，随参考和项目调整。既包含确定的参考字，也包含未在图片中出现过的独体、左右、上下结构字。繁简双范围加入“叶葉、风風、云雲、书書”等配对及共形字；不擅改“发/發/髮”等语义关联。显示同字对照、标题与一小段用户文案，明确小样字数，提供实际字体渲染结果。问“更喜欢哪一个？哪些地方想更尖、更圆、更宽或更轻？”而不是让用户批准技术步骤。

**扩展确认**：参考轮廓提取成功，只证明那些已给出的字贴合；在扩整库前展示新字、新文案及复杂字，检查字面、笔形和气质是否一致。用户只认可一个字时，不默认其认可任意底库全套；用户已明确要求直接扩整套时完成可审阅设计版，并如实说明设计来源与待反馈部分，不额外阻断。

反馈要变成具体改动：如“保留端点，把中宫放松，收窄撇捺弧度”，记录在项目 brief/配方。沿用已确认的参考、文案与设计规则；用户换风格或简繁时只重开受影响的选择。

## 项目 brief 建议记录

用途与尺寸；输出简繁范围；优先地区和是否已定；一字体兼容/分地区文件；参考清单与各自角色；保留/避免的特征；必需文字；字重；目标字表；已确认样张；用户最后反馈；允许代理自主决定的事项。保存在具体项目中，不把用户这一次的选择写成所有任务默认值。

## 对话使用示例

用户：“做一个科技感中文字体。” → 补问用途、简繁范围，并邀请参考；用户没有图则提供不同方向的小样。

用户：“参考繁体招牌，但我要简体。” → 记录简体，迁移笔形，不能只把目标字转换为繁体。

用户：“这个葉很好，做整套。” → 保留确认的葉，展示或随完整设计版附上新字延展效果，清楚列出底库/规则处理范围；不宣称从照片恢复了整个原字体。

用户：“简繁都要，你决定，直接完整包。” → 用已有信息选合适底库和优先地区，分别核验简繁覆盖，完成完整包；不再重复询问是否要参考或是否可以导出。
